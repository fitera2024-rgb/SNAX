# Календарный график SNAX v3.0

Дата пересчёта: **25 августа 2026**.  
База: паспорт проекта v1.0 (34 недели от T0) + реестр v1.2 + фактический статус WORK-001…009 + отсутствие выгрузок баз.

## 1. Зачем пересчитывать

Паспорт задавал относительные недели 1–34 без календарных дат, без праздников РФ 2026–2027 и без явной зависимости G1 от выгрузок 1С. ТЗ v2.0 оценивало только контур «файл → заказ/приёмка» в 9–14 недель — это **не** горизонт всей программы.

Пересчёт не обещает более ранний G4 из-за merged WORK-001…004: фундамент сервиса готов, но пилоты 1С, НСИ, обмены и расширения ждут данные и решения D-01…D-48.

## 5. Сценарий B — выгрузки позже G0

`dumpLagWeeks = ceil((дата_манифеста − 11.09.2026) / 7)`, минимум 0.

| Правило | Формула |
|---|---|
| G1 | 09.10.2026 + `dumpLagWeeks` недель, но не раньше чем манифест + 4 недели |
| G2 | G1 + 4 недели |
| G3 | max(22.01.2027, G2 + 8 недель) |
| G4 | G3 + 4 недели |
| G5 | G4 + 6 недель |
| G6 | G5 + 3 недели, с выравниванием до пятницы до 01.05 если возможно |
| G7 | G6 + 3 недели, не в период 01–10.05 |

Пример: манифест 02.10.2026 → dumpLag ≈ 3 нед. → G1 ≈ 30.10, G2 ≈ 27.11, G3 остаётся 22.01 (лаг < порога параллельного P3), G7 ≈ конец мая 2027.

Пример: манифест 01.12.2026 → G1 ≈ 29.12, фактически после НГ ≈ 22.01.2027; G7 уходит в июнь 2027. Steering обязан переутвердить scope, а не «догнать» сокращением UAT.

## 6. Сценарий C — ресурсы ниже D-28

Если нет выделенного 1С-разработчика параллельно backend:

- P4 и P5 выстраиваются последовательно полностью;
- к сценарию A добавляется **+6…8 недель** на G5–G7;
- G7 базовый сдвигается с 14.05.2027 примерно на **конец июня 2027**.

Точная цифра фиксируется после D-28, не угадывается в коде.

## 7. Критический путь

```text
выгрузки → каталоги MDM/обмены/расширения → G1
                ↘
формулы/НСИ (G2) → staging УТ → G4 заказ → G5 приёмка → G7

параллельно: P3 сервис (WORK-005…015) ──→ G3
```

Не на критическом пути до G2: production BI, MAXMA сверх D-36, OCR, таможенный контур.

Блокеры T0-недели: D-29 CI billing, D-30 merge chain, D-47 манифест, GOV-003 активы подрядчика.

Очередь конкретных действий (AP-0…AP-8, две оси «архитектура / доработки AS-IS»): [TECHNICAL_ACTION_PLAN.md](TECHNICAL_ACTION_PLAN.md).

## 11. Правило дальнейших пересчётов

Новый график выпускается только если:

- изменился dumpLag более чем на 1 неделю;
- D-28 утверждён иначе, чем модель паспорта;
- steering вырезал или добавил поток (например, MAXMA в MVP).

Пересчёт оформляется версией SCHEDULE (3.1+) и строкой в decision log. Даты в PROJECT_CONTRACT обновляются тем же PR.
