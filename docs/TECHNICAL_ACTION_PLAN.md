# 2. Две оси работ — не смешивать в одном PR

```text
Ось A. АРХИТЕКТУРА (строим целевой контур)
  сервис нормализации  →  контракты  →  API/polling
  каталоги MDM/обмены/расширения (после дампа)
  новое расширение УТ в onec-extension/
  топология ADR-004: спутник только центральной УТ

Ось B. ДОРАБОТКИ AS-IS (лечим текущий ландшафт)
  14 расширений: паспорт → disposition → rehearsal/rollback
  обмены: непроведённые ≠ успех; мониторинг ARC-010
  MDM: магазин–склад–касса–организация–узел
  формулы, факт продажи D-44, БДС/P&L, Frontol coexistence
  ПомощникЗакупок: разложить, не переносить
```

| Правило | Смысл |
|---|---|
| Ось A не ждёт полной оси B, кроме G1/G2 для пилотов | Readers и package можно делать на синтетике |
| Ось B не ждёт готового сервиса | Контрольный день и паспорта расширений можно начать на копии 1С |
| Пилот заказа (G4) требует обеих осей | G2 формулы + G3 package + staging УТ |
| Не переписывать типовую конфигурацию | Доработки — расширения + штатные механизмы |
| Не строить второй расчёт заказа вне 1С | Сервис заканчивается на `import-package` |
