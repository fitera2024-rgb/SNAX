# Приём выгрузок информационных баз SNAX

Версия 1.0 · 25 августа 2026 · связан с D-47, TASK-037…040, контрактами `config-dump-manifest` и каталогами MDM/расширений/обменов.

## 1. Зачем этот документ

Рабочие базы 1С ещё не выгружены. Когда они появятся, команда должна:

1. принять файлы без попадания payload в Git;
2. зарегистрировать манифест по схеме;
3. разобрать метаданные в каталоги;
4. повысить статус объектов с `UNVERIFIED` до `VERIFIED`;
5. не менять архитектурные инварианты без ADR.

Выгрузка не заменяет ТЗ и не разрешает прямой доступ сервиса к БД 1С.

## 2. Что считать выгрузкой

Допустимые носители (уточняет D-47):

| Вид | Типичные файлы | Использование |
|---|---|---|
| Конфигурация | `*.cf`, `*.cfe`, XML выгрузка конфигурации | Релиз, объекты, расширения |
| Данные тестовой копии | `*.dt`, выгрузка выбранных справочников | MDM, контрольный день |
| Реестр расширений | XLSX/CSV или разбор CF | Паспорта CFG-001 |
| Логи обмена | TXT/JSON обезличенные | Каталог маршрутов |
| Скрин/протокол | PDF | Evidence G1, не источник истины |

Не является выгрузкой и не обрабатывается этим контуром: прайс поставщика (это import-package), УПД (receipt-package), production `.env`.

## 3. Как передавать

1. Заказчик кладёт файлы в согласованное хранилище вне Git (S3/MinIO bucket `dumps/incoming/`, SFTP или физический носитель).
2. Рядом кладётся `manifest.json` по схеме `contracts/schemas/config-dump-manifest.schema.json`.
3. Считаются SHA-256 каждого файла; они обязаны совпасть с манифестом.
4. Исполнитель копирует **только манифест и checksums** в репозиторий (example или `docs/research/<date>/manifest.sanitized.json` без путей хранилища).
5. Разбор выполняется на изолированной TEST-машине без записи payload в working tree.

Object key формирует сервис/оператор, не пользовательский путь.

## 4. Обязательные поля манифеста

- `schemaVersion`, `intakeId`, `receivedAt`, `sourceOwner`;
- `classification` и `gitPolicy=DO_NOT_COMMIT_PAYLOAD`;
- список `bases[]`: `baseCode`, `contour`, `platformVersion`, `configurationName`, `configurationVersion` (если неизвестно — `null` + `unknownReason`);
- `artifacts[]`: `fileName`, `mediaType`, `sha256`, `sizeBytes`, `kind`;
- `period.start` / `period.end` среза данных, если есть dt;
- `sanitization`: что уже маскировано;
- `intendedUse`: `CATALOG | RECONCILIATION | UAT | EXTENSION_AUDIT`.

Манифест с `gitPolicy` иным, чем `DO_NOT_COMMIT_PAYLOAD`, для `CONFIDENTIAL`/`RESTRICTED` **отклоняется** схемой invalid-фикстурой и политикой TASK-037.

## 5. Порядок разбора (когда файлы уже есть)

1. Quarantine: MIME/signature, размер, антивирус по политике.
2. Сверка checksum.
3. Инвентаризация конфигурации → черновик `extension-passport`.
4. Справочники организаций/складов/касс/магазинов → черновик `mdm-object-catalog` (коды можно публиковать; наименования магазинов — по D-08).
5. Планы обмена / настройки синхронизации → `exchange-catalog`.
6. Выбор контрольного магазина/дня совместно с финансами → `store-day-reconciliation` на TEST.
7. Steering: перевод записей в `VERIFIED`.

Не делать на этом шаге: перепроведение рабочей базы, отключение расширений, загрузку дампа в PROD.

## 6. Что можно сразу коммитить после разбора

- обезличенный каталог кодов и GUID тестовой копии, если заказчик подтвердил;
- числовые счётчики без сумм (`documentCount`, `postedCount`, `errorCount`);
- имена расширений, режимы совместимости, флаги закрытого кода;
- SHA-256 артефактов.

Нельзя коммитить: dt/cf, строки документов, цены, ИНН контрагентов, ФИО сотрудников, connection strings.

## 7. Синтетический режим до выгрузок

До D-47 команда использует examples в `contracts/examples/`:

- одна demo-база `UT_CENTRAL`;
- два demo-магазина;
- три demo-расширения, среди них аналог закрытого кода;
- один demo-маршрут обмена;
- один demo-день сверки с decimal-строками.

Это позволяет зелёные contract tests и TASK-037 без реальных баз.

## 8. Сдвиг плана

Если манифест не зарегистрирован до G0 (11.09.2026):

- G1 не открывается;
- P3 (сервис на synthetic fixtures) продолжается;
- G1 = дата_регистрации_манифеста + 4 недели (см. SCHEDULE.md);
- последующие gates сдвигаются на тот же лаг, кроме G3, который сдвигается только если лаг > 3 недель (платформа может идти параллельно).

## 9. Acceptance приёмки выгрузки

| ID | Проверка |
|---|---|
| DI-AC-001 | Манифест проходит schema; invalid fixtures отклоняются |
| DI-AC-002 | Повтор SHA-256 не создаёт второй intake |
| DI-AC-003 | Working tree Git не содержит dt/cf/binaries выгрузки |
| DI-AC-004 | Каждая заявленная база имеет запись каталога со статусом |
| DI-AC-005 | 14 расширений исходного анализа сопоставлены с фактическими именами либо задокументирован delta |
| DI-AC-006 | Нет секретов в манифесте (pattern scan) |
