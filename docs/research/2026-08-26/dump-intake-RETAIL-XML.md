## 2. Чем это является — и чем нет

Это **выгрузка метаданных справочников конфигурации 1С** (`MetaDataObject` / `Catalog`), а не:

- выгрузка **данных** информационной базы (элементы магазинов, документы, суммы);
- полный дамп конфигурации (`Configuration.xml`, документы, регистры, планы обмена);
- `*.cf` / `*.cfe` / `*.dt`.

В корне архива только `РозницаXML/Catalogs/…`. Релиз платформы и конфигурации из этого файла **не читается** (D-01 для Розницы остаётся открытым).

Формат XML: `version="2.21"` у `MetaDataObject` — это версия формата выгрузки, не номер Розницы.

## 3. Что это значит для MDM (MDM-001)

В этой базе **нет** справочника `Магазины`. Точка и склад живут в типовом для УНФ/Розницы объекте **`СтруктурныеЕдиницы`** (иерархия элементов, реквизит `ТипСтруктурнойЕдиницы`).

Связанные типовые справочники, полезные для таблицы соответствий:

| Справочник | Зачем |
|---|---|
| `Организации` | юрлицо |
| `СтруктурныеЕдиницы` | магазин / склад / подразделение |
| `Кассы`, `КассыККМ` | касса точки |
| `ПодразделенияОрганизаций` | подразделение |
| `снэксРегионы` | регион Форус, не типовой |

Пока нет DT/XML **данных**, заполнить GUID магазинов нельзя. Каталог MDM остаётся пустым по экземплярам.

## 4. След «Форус» в метаданных

Отдельный справочник и реквизиты с синонимом `[ФОРУС]`:

| Объект | Имя | Смысл |
|---|---|---|
| Справочник | `снэксРегионы` | `[ФОРУС] Регионы` (код 9, наименование 25, без своих реквизитов в XML) |
| `СтруктурныеЕдиницы` | `снэксРегион` | регион на точке/складе |
| `СтруктурныеЕдиницы` | `снэксЗакупочнаяЦена` | закупочная цена на структурной единице |
| `ВидыЦен` | `снэксРегион` | регион на виде цены |
| `Пользователи`, `Сотрудники` | `снэксСклад` | структурная единица (склад) |
| `Пользователи`, `Сотрудники` | `снэксКассир` | признак кассира |

Модулей `.bsl` с текстом «снэкс»/«форус» в этом архиве нет (логика может быть в документах/расширениях, которых в zip нет).

Это **не** 14 расширений УТ (CFG-001). Это доработки **самой Розницы** (встроенные реквизиты). Disposition D-37 по УТ этим файлом не закрывается.

## 5. Оборудование offline / Frontol (CFG-006)

В каталогах есть типовые `ОфлайнОборудование` и `ПравилаОбменаСПодключаемымОборудованиемOffline`. Это намекает на контур КСО/offline, но **не** доказывает, что Frontol ещё в проде: нет планов обмена, логов и списка оборудования.

## 6. Чего не хватает для D-47 / G1

| Нужно дальше | Зачем |
|---|---|
| `Configuration.xml` или CF той же базы | релиз, совместимость, список подсистем |
| Documents / ExchangePlans / InformationRegisters | обмены, документы поступления, узлы |
| Расширения `*.cfe` или папка `Ext` конфигурации | CFG-001 для Розницы |
| Выгрузка **данных** (DT или XML справочников с элементами) на TEST | MDM GUID, контрольный магазин |
| То же для `UT_CENTRAL`, legacy УТ, БП | G1 цепочка Розница → УТ → БП |

Пока этот набор неполный, **G1 не открывается**. P3 сервиса на синтетике продолжается. Сценарий B (`dumpLagWeeks`) применяется, когда зарегистрирован **полный** манифест D-47, а не один частичный ZIP.

## 7. Что не делать с этим архивом

- не коммитить zip и распакованный XML;
- не грузить в PROD;
- не объявлять карту магазинов VERIFIED;
- не угадывать релиз Розницы и состав 14 расширений УТ.

## 8. Следующее действие
