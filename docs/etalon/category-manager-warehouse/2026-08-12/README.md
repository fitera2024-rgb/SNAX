## Что считается эталоном

1. **Комплект из трёх самостоятельных артефактов:** основной AS-IS-отчёт, доказательная сводка процессов и отдельный чек-лист договорённостей.
2. **Разделение доказательности:** факт, показанный на экране; устное подтверждение; документальное подтверждение; рабочая гипотеза; процесс, не показанный в записи.
3. **Сквозная структура основного отчёта:** резюме → роль → системы и данные → каталог процессов → подробные AS-IS-процессы → риски → требования → показатели и формулы → предварительная TO-BE-концепция → срочные действия → план верификации → открытые вопросы → история версий.
4. **Отсутствие пустых приложений.** В основной отчёт включаются только заполненные материалы; невыполненные запросы и будущие демонстрации выносятся в отдельный чек-лист.
5. **Проверяемость выводов:** для ключевых утверждений указываются источник, таймкод, экран, документ, ограничение и требуемый следующий шаг.
6. **Раздельная фиксация фактов и проектных решений:** описание AS-IS не подменяется предложениями автоматизации.
7. **Визуальная пригодность для печати:** схемы и таблицы не выходят за границы страницы, заголовки и нумерация единообразны, на титуле указан статус версии.
8. **Версионность:** новая редакция не уничтожает предыдущую; изменения отражаются в журнале версий и сопровождаются новой контрольной суммой.

## Правило применения в следующих интервью

Для каждого нового функционального блока используется тот же пакет:

- основной отчёт по роли и процессам AS-IS;
- отдельная сводка доказательств со скриншотами и таймкодами;
- отдельный конкретный чек-лист того, что сотрудник должен передать или показать;
- явные статусы достоверности по каждому процессу;
- реестр рисков и требований с приоритетами;
- план следующей верификации на реальных сквозных примерах.

## Правило обновления эталона

1. Не заменять этот комплект без отдельного решения руководителя проекта.
2. Для новой эталонной редакции создать соседний каталог с датой выпуска.
3. Сохранить предыдущую редакцию и добавить новую строку в корневой индекс репозитория.
4. Для каждого исходного файла указать версию, размер и SHA-256.
5. В описании коммита явно указывать, что изменилось в форме эталона.
