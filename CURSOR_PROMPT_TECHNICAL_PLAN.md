# Промпт для Cursor — технический план по папке файлов и выгрузкам баз

Скопируйте блок ниже целиком в новый чат Cursor или в Cursor Cloud Agent по репозиторию `fitera2024-rgb/SNAX`. Базовая ветка: `main`.

---

Ты работаешь в репозитории **SNAX Order Import** (`fitera2024-rgb/SNAX`) как Cursor-агент.

Составь технический план проекта: **что можно сделать, имея доступ к папке исходных файлов и выгрузкам информационных баз**, без прямого доступа сервиса к живой БД 1С.

## Контекст доступа

Предполагай два источника, пути подставь по факту, если они есть в окружении; если путей нет — явно опиши допущения и минимальный запрос материалов.

1. **Папка файлов:** прайс-листы и бланки заказа поставщиков (`XLS`, `XLSX`, `CSV`), повторные версии шаблонов, при наличии — УПД/накладные/PDF/XML. Это тот же тип корпуса, что в ТЗ: 26 файлов, 20 профилей.
2. **Выгрузки баз:** копия/выгрузка 1С:УТ (предпочтительно `.dt` для изолированной тестовой ИБ, `.cf/.cfe`, табличные срезы номенклатуры, штрихкодов, номенклатуры партнёров, упаковок, складов, способов обеспечения). Если есть Розница — отдельно. SQL-дамп 1С допустим только как материал обследования.

## Что сдать

Создай документ `docs/plans/TECHNICAL_PLAN_FOLDER_AND_DUMPS.md` и ссылку на него из `README.md`.

План должен ответить по делу, не пересказывать ТЗ целиком:

1. что уже есть в репозитории и чего нет;
2. что даёт только папка файлов;
3. что дают только выгрузки баз;
4. что даёт пересечение (покрытие matching, контрольные SKU, файловый пилот);
5. что делать нельзя даже при полном доступе;
6. последовательность волн A/B/C, привязанная к `TASK-*` / `WORK-*`;
7. какие D-решения данные приближают, а какие нет;
8. какие артефакты появятся в Git, а какие должны остаться вне репозитория;
9. минимальный запрос, если состав доступа неполный;
10. критерий успеха этого окна доступа и следующее действие.

Пиши по-русски. Не оценивай работу в календарных днях и неделях: описывай технические шаги, зависимости и риски.

## Жёсткие запреты

- Не подключай сервис к таблицам БД 1С и не проектируй это как канал интеграции.
- Не рассчитывай потребность и не создавай заказ поставщику во внешнем сервисе.
- Не утверждай связи по похожести названия.
- Не коммить `.env`, `.dt`, `.cf`, прайсы, УПД, цены, остатки и персональные данные.
- Не исполняй макросы, формулы и внешние ссылки Excel.
- Не проводи попутный рефакторинг кода и не реализуй readers/1С в этой работе.
- Не меняй публичные контракты.

Это документальная работа, не код-фича. Один PR в `main` с планом достаточно.

## Как запустить в Cursor

1. Откройте репозиторий `SNAX`.
2. Новый Agent chat / Cloud Agent, модель с сильным reasoning.
3. Вставьте блок выше.
4. Если папка или выгрузки уже лежат на диске, допишите в конец фактические пути, например:

```text
Папка файлов: <путь>
Выгрузки баз: <путь>
```
