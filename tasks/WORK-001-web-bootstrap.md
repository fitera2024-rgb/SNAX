## Режим выполнения в Codex Cloud

Codex Cloud может выдавать изолированный checkout со следующими особенностями:

- локальная ветка называется `work`;
- `git remote -v` пуст;
- GitHub CLI не авторизован;
- прямой `git fetch` из sandbox недоступен;
- публикация выполняется не shell-командой, а встроенным действием Codex Cloud.

Это штатный режим и **не является блокером**. Нельзя прекращать работу только из-за отсутствия remote, `gh auth` или локальной ветки с именем `work/001-web-bootstrap-impl`.

Порядок:

1. Работать в текущем checkout Codex Cloud.
2. Реализовать WORK-001 полностью.
3. Создать локальный commit.
4. Через встроенное действие Codex Cloud опубликовать изменения в ветку `work/001-web-bootstrap-impl` и создать PR в `main`.
5. Если публикация временно недоступна, завершить реализацию, проверки и локальный commit, затем сообщить SHA и не объявлять код потерянным.

PR №4 является подготовительным PR с task card и правилами выполнения. Он не является реализационным PR WORK-001.

## Цель

Создать воспроизводимый каркас внешней части SNAX и первый web-интерфейс, на котором далее будут реализованы загрузка файлов поставщиков, профили импорта, нормализация, контроль качества и обмен с 1С.

## Результат работы

1. Monorepo-каркас без удаления существующего каталога `docs/etalon`.
2. Backend baseline на Python 3.12+ и FastAPI.
3. Web baseline на React + TypeScript + Vite.
4. Docker Compose с PostgreSQL, Redis и MinIO.
5. Lint, typecheck, tests, contract validation и CI.
6. Первый интерфейс в стиле SNAX с русской локализацией.
7. Фактические команды запуска в README.

## Обязательные backend-функции

- `GET /health`;
- `GET /version`;
- environment configuration;
- структурированные логи;
- стабильный формат ошибок;
- unit/API tests;
- отсутствие domain-бизнес-логики в HTTP handlers.

## Обязательные web-маршруты

- `/` — дашборд;
- `/imports` — список импортов;
- `/imports/new` — новая загрузка;
- `/imports/:id` — карточка импорта;
- `/profiles` — профили поставщиков;
- `/settings` — настройки.

## UI-стиль

- светлый деловой фон;
- глубокий сине-графитовый sidebar;
- бирюзовый акцент;
- белые карточки;
- компактные таблицы;
- чёткие status badges;
- без градиентов и визуального шума;
- desktop-first 1366–1440 px, адаптация минимум до 390 px;
- интерфейс на русском языке.

## Экран «Дашборд»

Mock-KPI:

- файлов сегодня;
- успешно обработано;
- требуют внимания;
- несопоставленных позиций;
- последние загрузки;
- действие «Загрузить файл».

## Экран «Импорты»

Колонки:

- дата и время;
- поставщик;
- файл;
- профиль;
- строк;
- ошибок;
- статус;
- действие «Открыть».

## Экран «Новая загрузка»

- drag-and-drop;
- выбор поставщика или автоопределение;
- допустимые форматы;
- подтверждение отсутствия персональных данных;
- mock-submit без реального ingestion.

## Экран «Карточка импорта»

- реквизиты файла;
- этапы обработки;
- резюме;
- вкладки «Строки», «Ошибки», «Протокол»;
- empty/loading/error состояния.

## Экран «Профили»

- карточки или таблица профилей;
- версия;
- статус;
- дата последнего успешного импорта;
- действие просмотра.

## Не входит

- чтение XLS/XLSX/CSV;
- реальные поставщики и коммерческие файлы;
- сопоставление номенклатуры;
- расчёт заказа;
- интеграция с 1С;
- production authorization;
- OCR и контур приёмки.

## Использование моделей

### GPT-5.3-Codex

Использовать для bootstrap, структуры, backend, frontend foundation, CI, интеграционных исправлений и финального прохода.

### GPT-5.3-Codex-Spark

Разрешён только для локальных изменений:

- правка одного или нескольких связанных React-компонентов;
- стили и токены;
- тексты интерфейса;
- небольшой component test;
- локальный рефакторинг без изменения контрактов.

Spark не меняет архитектуру, публичные контракты, CI, зависимости или структуру репозитория без отдельной task card. Для каждой Spark-задачи явно указать команды тестов.

## Acceptance criteria

1. Команды README воспроизводимо запускают API и web.
2. `/health` возвращает HTTP 200 и стабильный JSON.
3. `/version` возвращает `SNAX`, версию и build metadata при наличии.
4. Все обязательные web routes открываются без runtime error.
5. Навигация работает и показывает активный раздел.
6. UI проверен на 1366 px и 390 px.
7. В Git нет реальных прайсов, персональных данных, токенов и `.env`.
8. Backend lint/typecheck/tests зелёные.
9. Frontend lint/typecheck/tests/build зелёные.
10. CI выполняет backend и frontend gates.
11. `docker compose config` проходит.
12. Выполнены Docker build/up и smoke test.
13. Изменения оформлены одним обозримым реализационным PR в `main`.

npm ci
